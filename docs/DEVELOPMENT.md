# Разработка и сборка

## Требования

- Git; Python 3.12 или новее для сборщика.
- Для компиляции помощника: Windows x64, .NET Framework 4.x с `Framework64/v4.0.30319/csc.exe`, системные `System.Drawing` и `System.Web.Extensions`.
- Для настоящего теста: собственная Steam-копия RE2, SteamVR / OpenVR и VR-шлем. Автотесты не включают игру.

Скачайте / клонируйте этот репозиторий и из его корня выполните:

```powershell
python tools/build_release.py --check
python tools/build_release.py
```

Сборщик компилирует helper, запускает два встроенных self-test **без отправки реального ввода и без инициализации OpenVR**, собирает `dist/RE2IVR-0.6.0-belt.zip` и проверяет ZIP / SHA256-манифест runtime.

По умолчанию официальный REFramework скачает установщик на целевом ПК. Для автономной RT-установки можно передать **официальный `RE2.zip` из REFramework v1.5.9.1**:

```powershell
python tools/build_release.py --framework-archive C:\Downloads\RE2.zip
```

Сборщик отклоняет архив с другим SHA256. Это RT-архив; для NonRT установщик получает другой официальный asset. Не подменяйте один другим.

На Linux можно проверить структуру исходников. Упаковка с `--prebuilt-helper` допустима только для точного ранее собранного helper 0.6.0: проверяются его SHA256 и исходники трёх C#-файлов. После изменения кода нужно компилировать заново на Windows. Этот режим не является новой проверкой исполнения Windows-кода.

## Структура

```text
runtime/       Lua bootstrap и модули REFramework
support/       C# helper, OpenVR bindings и лицензия Valve
installer/     CMD / PowerShell, копируемые в установочный пакет
tools/         Сборка и происхождение восстановленного снимка
docs/          Дизайн, запуск, проблемы и статус тестирования
third_party/   Уведомления о зависимостях
```

Источником runtime служит `runtime/`, не временная папка `build/`. Редактируйте исходники и собирайте пакет заново. В git не должны попадать `installed-location.json`, отчёты с тестового ПК, framework ZIP, DLL, EXE, сохранения и личные настройки.

## Версии и публикация

Для первого создания публичного репозитория из подготовленного снимка можно запустить корневой `Publish-GitHub.cmd`. Нужны установленные Git и официальный [GitHub CLI](https://cli.github.com/). Скрипт предложит штатный web-вход CLI, создаст **новый публичный** `RE2-Immersive-VR` в выбранном CLI аккаунте и отправит исходники. Он не заменяет существующий `origin`, не перезаписывает существующий репозиторий и не делает force push. Проверьте выбранный аккаунт перед подтверждением входа. Пароль и токен в чат передавать не нужно. Если доступно прямое создание / заполнение через подключение GitHub, этот вспомогательный скрипт не требуется.

`VERSION` должен совпадать с `local VERSION` в bootstrap. Обновляйте CHANGELOG и статус проверки. Готовые ZIP размещаются в GitHub Releases, а не коммитятся как игровые бинарники в исходное дерево.

Windows workflow собирает ZIP в Actions artifact. Он не публикует релиз и не запускает игру автоматически. Перед созданием релиза просмотрите содержимое пакета и результаты проверок. Для первого release можно использовать существующую проверенную Windows-сборку 0.6.0; её происхождение записано в `tools/source_provenance.json`.

Оригинальная Windows-папка проекта временно недоступна, поэтому этот снимок восстановлен из установочного архива. Он содержит production Lua, C#, SDK-лицензии и установщик, но не все ранние исследовательские probe-фикстуры. Не утверждайте, что отсутствующие тесты выполняются в новом CI.
