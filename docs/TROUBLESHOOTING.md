# Диагностика

## RE.NET: Space вместо неточного клика

Запускать через текущий `Play.cmd`. В Insert выберите **Controller dialog input: space**, закройте меню, удерживайте **левый grip + правый B 1 секунду**. Если Space не принимается текущим окном, выберите `enter`.

**Send real space after Insert closes** — явная одноразовая команда с ожиданием закрытия Insert до 10 секунд. Её можно использовать для нераспознанного окна игры. Контроллерная комбинация требует обнаруженного меню / диалога, чтобы не отправлять случайный клик во время стрельбы.

Режим `mouse` не ищет кнопку подтверждения: курсор должен уже находиться на ней. Можно навести его в SteamVR Desktop, затем закрыть панель. Снимание шлема не является требованием ни одного из этих способов.

Старые варианты **Close current error dialog** и **Force dismiss current error dialog** вызывают методы GUIMaster. Они не гарантируют закрытия специализированных интерфейсов. Помощник ввода добавлен, поскольку простого скрытия general dialog было недостаточно на тестовом ПК.

Статусы помощника, доступные через **Refresh input helper status**:

| Статус | Значение |
|---|---|
| `ready` | Помощник запущен |
| `input_sent` | Windows приняла события; закрытие игрового окна не подтверждено |
| `game_not_foreground` | Главное окно RE2 не в фокусе |
| `cursor_outside_game` | Курсор находится за пределами клиентской области RE2 |
| `release_desktop_buttons` | Нужно отпустить нажатые кнопки мыши / клавиши-модификаторы |
| `input_blocked` | Windows не приняла ввод; возможен разный уровень привилегий процессов |
| `modal_or_non_game_window_rejected` | Это не главное окно игры, например системный Fatal Error |

Не повышайте привилегии приложений без необходимости. Помощник не предназначен для подтверждения системных окон, установки программ или обхода ограничений Windows.

Для отключения статистики: главное меню RE2 → Options → RE NET → Play Data Settings → Off. [Описание RE.NET от Capcom](https://game.capcom.com/residentevil/uk/qa-two.html).

## Резко упал FPS, вентиляторы шумят

1. Запишите текущие значения и верните разрешение **только приложения RE2** в SteamVR к 100%, если ранее повышали его. Это отдельный параметр от разрешения зеркала на мониторе.
2. Проверьте потребление видеопамяти и настройки самой игры. Этот мод не определяет автоматически подходящее качество для вашего GPU.
3. Если REFramework пишет **Hardware scheduling: Enabled**, проверьте выключение «Планирование графического процессора с аппаратным ускорением» в настройках графики Windows. Для применения потребуется перезагрузка. Это рекомендуемый upstream шаг при крайне низком FPS, не доказательство причины каждого вылета.
4. Выключите пояс через **Hide SteamVR spatial belt** и сравните тот же участок. Его нагрузка в реальной игре ещё не измерена.
5. Не меняйте одновременно несколько параметров: так невозможно отделить причину от совпадения.

См. [официальную диагностику REFramework](https://cursey.github.io/reframework-book/troubleshooting/VR-Troubleshooting.html). Автоматическое изменение HAGS, драйвера, глобальных параметров SteamVR или системной безопасности не выполняется.

## Не вернулся VR после надевания шлема

В 0.5.4 потеря / невалидная поза стала временным `inactive`, а не причиной постоянного отключения мода. В standby прекращается постоянный опрос инвентаря. После возврата валидного трекинга отпустите и снова зажмите правый grip.

В REFramework уже есть собственная переинициализация OpenVR после возвращения активности шлема. Мод не запускает вторую одновременно. Зависание композитора или потерянное D3D-устройство такой логикой не восстанавливаются. Если игра продолжает зависать, приложите версию билда и диагностику; реальное устранение этого сбоя пока не подтверждено.

## Fatal D3D error 22 / 25

Сохраните полный текст, включая имя файла, строку, DXGI-ошибку и HRESULT, если они есть. Один номер не устанавливает причину. Эти сообщения не являются окном статистики RE.NET. После фатального сбоя рендерера закройте и перезапустите игру.

Ранее сообщалось `renderdevicedx12.cpp`, строка 274, Fatal D3D error (22); позже — номер 25. Изменения обработки трекинга, отключение Mesh-копий и правки FPS являются попытками снизить риски регрессии, а не подтверждённым исправлением этих ошибок.

## Руки / тело разные в двух глазах

Upstream описывает проблему RT-костюмов: [#400](https://github.com/praydog/REFramework/issues/400), [#906](https://github.com/praydog/REFramework/issues/906). Среди обходов — другой костюм и доступная в Steam ветка `dx11_non-rt`.

Чтобы попробовать NonRT: закройте игру → Steam → RE2 → Свойства → Бета-версии → `dx11_non-rt`, если она доступна → дождитесь загрузки → повторите `Install.cmd` для выбора соответствующего фреймворка. Не копируйте RT DLL вручную в NonRT-игру. Установщик сам ветку Steam не переключает.

Не меняйте IPD или проекции глаз для исправления отсутствующей геометрии. OpenXR not loaded / OpenVR loaded first ожидаемо при выбранном OpenVR; само по себе сообщение не требует удаления DLL.

## Пояс отсутствует

- Нужен **SteamVR / OpenVR**, а не только OpenXR.
- Запускайте текущий `Play.cmd` либо `Start-Input-Bridge.cmd` для уже работающей игры.
- Проверьте **Show SteamVR spatial belt** и **Refresh SteamVR belt status**.
- Пояс скрывается при неактивном трекинге, неподходящей сцене и устаревшем пакете состояния.
- Плоскости ориентированы на голову и используют standing tracking space. Совпадение с другими tracking-origin конфигурациями ещё не проверено.
- Усталый / нераспознанный ресурс не заменяется выдуманным предметом. `0` у слота означает отсутствие доступного количества или данных для выбранного оружия.

Настоящие игровые Mesh-копии остаются выключенными. Их старый переключатель не является способом включения нового пояса.

## B не пополняет патроны

В 0.6.0 по умолчанию обычная перезарядка правой B. Если вручную включён **experimental physical reload**, верните **Use native button reload**. Проверьте, что есть подходящие патроны и магазин не полон. При перезарядке продолжайте удерживать правый grip.

При срабатывании проверки расхода или неопределённом результате транзакции мод может заблокировать текущую экспериментальную механику. Не повторяйте вручную неизвестную запись боеприпасов и не редактируйте сохранение. Соберите отчёт; в меню есть отдельный **Recovery: native shooting and reloads**.

## Что прикладывать к Issue

`Collect.cmd` собирает выбранные JSON-отчёты мода и графические параметры. Для пояса важны `re2ivr_belt_status.json`, `re2ivr_belt.json`; для окна — `re2ivr_input_bridge.json`; для боеприпасов — transaction / ammo fault отчёты, если они существуют.

Просмотрите содержимое ZIP перед публичной отправкой. Полные логи и сохранения по умолчанию не публикуются. Укажите точные шаги, версию 0.6.0, RT/NonRT, костюм, GPU/драйвер, способ связи с Quest и ожидаемое поведение.
